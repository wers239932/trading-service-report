# Quotation Receiver: Структура приложения

## Назначение

`quotation-receiver` — это сервис на Go, который:

1. опрашивает символьное устройство Linux;
2. парсит бинарные фреймы котировок от драйвера;
3. формирует JSON-события тикеров;
4. публикует события в Redis Pub/Sub.

## Архитектура верхнего уровня

Сервис разбит на небольшие внутренние пакеты с четкими зонами ответственности:

- `main.go`: связывание компонентов и запуск приложения.
- `internal/config`: загрузка и валидация конфигурации из окружения.
- `internal/driver`: низкоуровневый цикл опроса `/dev/...` через `read()`.
- `internal/processor`: парсинг бинарных фреймов и конвертация цены из копеек в рубли.
- `internal/ticker`: JSON-сериализация событий тикера.
- `internal/pubsub`: реализация Redis-публикатора.

## Поток данных

1. `main.go` загружает настройки из окружения (`config.Load()`).
2. `main.go` создает:
  - Redis-публикатор (`pubsub.NewRedisPublisher`),
  - процессор фреймов (`processor.NewFrameProcessor`).
3. `main.go` запускает цикл опроса (`driver.PollDriver`).
4. `PollDriver` читает сырые байты из `DEVICE_PATH` и передает чанки в `FrameProcessor.HandlePayload`.
5. `FrameProcessor`:
  - буферизует частичные чтения,
  - извлекает фиксированные 12-байтовые фреймы,
  - парсит поля фрейма (`ticker`, `price_kopecks`),
  - конвертирует целочисленные копейки в рубли,
  - сериализует событие в JSON через `ticker.SerializeEvent`.
6. Сериализованный JSON публикуется в Redis-канал через `publisher.Publish`.

## Детали поведения во время выполнения

- Процессор устойчив к разбиению чтений: один `read()` может содержать половину фрейма, ровно фрейм или несколько фреймов.
- Цена фрейма трактуется как абсолютное значение в копейках и конвертируется так:
  - `price_rub = price_kopecks / 100`.
- При корректном сигнале остановки (`SIGTERM`/`Ctrl+C`) опрос прекращается через отмену контекста.

# Quotation Receiver: Конфигурация и формат данных драйвера

## Переменные окружения

Сервис читает конфигурацию из переменных окружения при старте.
Если переменная не задана, используется значение по умолчанию.

| Variable | Type | Default | Description |
|---|---|---|---|
| `DEVICE_PATH` | string | `/dev/price_delta` | Путь к символьному устройству, предоставляемому драйвером ядра. |
| `BATCH_FRAME_COUNT` | int | `16` | Количество 12-байтовых фреймов, ожидаемых в одном низкоуровневом буфере чтения. Итоговый размер буфера чтения равен `12 * BATCH_FRAME_COUNT`. Должно быть `> 0`. |
| `POLL_MIN_DELAY_MS` | int | `1` | Минимальная задержка (мс) между успешными итерациями опроса. Должно быть `>= 0`. |
| `POLL_ERROR_BACKOFF_MS` | int | `10` | Задержка (мс) после повторяемых ошибок чтения. Должно быть `>= 0`. |
| `REDIS_ADDR` | string | `localhost:6379` | Адрес сервера Redis для публикации в Pub/Sub. |
| `REDIS_PASSWORD` | string | `` | Пароль Redis (опционально). |
| `REDIS_DB` | int | `0` | Индекс логической базы Redis. Должно быть `>= 0`. |
| `REDIS_CHANNEL` | string | `quotes.ticks` | Канал Redis Pub/Sub, куда публикуются JSON-события тикеров. |

## Формат полезной нагрузки драйвера (binary)

Драйвер должен отправлять бинарные фреймы фиксированного размера **12 байт**.
Фреймы могут приходить по одному или пачками; сервис буферизует байты и последовательно парсит полные фреймы.

### Разметка фрейма

| Offset | Size | Type | Field | Notes |
|---|---|---|---|---|
| `0` | `8` | bytes | `ticker` | ASCII-символ тикера. Если короче 8 байт, дополняется `\x00` или пробелами. |
| `8` | `4` | int32 | `price_kopecks` | Абсолютная цена в копейках, **int32**, **little-endian**. |

Итого: `8 + 4 = 12` байт.

### Правила декодирования в сервисе

1. `ticker`: байты `[0:8]`, обрезает `\x00` и пробелы.
2. `price_kopecks`: bytes `[8:12]`, декодируется как little-endian `int32`.
3. Перед публикацией конвертируется в рубли:
  - `price_rub = float32(price_kopecks) / 100`
4. Сервис генерирует JSON-событие:

```json
{
  "ticker": "AAPL",
  "price": 101.25,
  "timestamp": "2026-03-17T12:34:56.789Z"
}
```

## Пример фрейма

Тикер: `AAPL` с абсолютной ценой `12345` копеек (рублей).

- Ticker bytes (8): `41 41 50 4C 00 00 00 00`
- Цена в копейках (`12345`): `0x00003039`
- Little-endian bytes: `39 30 00 00`

Полный фрейм (12 bytes):

```text
41 41 50 4C 00 00 00 00 39 30 00 00
```

## Формат публикации Redis Pub/Sub

Каждый распарсенный фрейм драйвера преобразуется в JSON-событие и публикуется в Redis Pub/Sub.

### Канал

- Имя Redis-канала берется из `REDIS_CHANNEL` (по умолчанию: `quotes.ticks`).

### Описание сообщения

Тело сообщения — UTF-8 JSON со следующей схемой:

| Field | Type | Description |
|---|---|---|
| `ticker` | string | Символ тикера, распарсенный из фрейма драйвера. |
| `price` | float32 | Абсолютная цена тикера в рублях (конвертируется из копеек). |
| `timestamp` | string (RFC3339) | UTC-время создания события. |

Пример отправляемого JSON:

```json
{
  "ticker": "AAPL",
  "price": 101.25,
  "timestamp": "2026-03-17T12:34:56.789Z"
}
```

Проверка подпиской через redis-cli:

```bash
redis-cli SUBSCRIBE quotes.ticks
```
